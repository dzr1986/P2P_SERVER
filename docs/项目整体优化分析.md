# 项目整体优化与分析

> 日期：2026-08-16  
> 范围：整个仓库（信令核 + 中继 + 客户端 SDK + 构建），不是只改 NatServer。  
> 配套：[`p2p_server优化完毕.md`](p2p_server优化完毕.md)、[`P2P服务器开发计划书.md`](P2P服务器开发计划书.md)。

---

## 1. 现在处于哪一档

本仓库已经不是「能打洞的 demo」，而是一套可私有化部署的 **有中心信令 IoT UID 平台**：

| 层 | 状态 |
|----|------|
| 信令核 `p2p_natserver` | 档 A（历史 P0–P8 仓库内核）已收口 |
| 中继 `p2p_proxy` | UDP + DERP TCP/TLS + 配额 + HMAC 注册 |
| 客户端核 `core/` | ICE / PathSelect / PunchPolicy / Session / IOTC |
| 观看/浏览器/国标 | **明确不做进主进程**（P9–P11） |

下一档差距主要在 **现网验收与旁路网关**，不在「再拆一个 NatServer 上帝对象」。

```
设备/App ──心跳/CONNECT──► NatServer（只建连）
                │
                ├─ 直连（ICE / TCP 打洞 / LAN）
                └─ 失败 ──► P2PProxy（只转发）
```

## 2. 本轮体检发现的真问题

对照旧报告 [`代码优化分析报告.md`](../代码优化分析报告.md)（2026-08-10/15）和上一轮信令核收口，**还值得改、且能在本仓库改完**的是：

### 2.1 客户端：ICE restart 完成检测漏报（测试 [16]）

`begin_ice_restart` 把旧 agent 挪到 `juice_prev` 继续扛媒体。新 agent 若迟迟不打 `CONNECTED`，`set_connected` 不会再走，「ICE restarted」日志就不出现。会话其实还在。

**修法**：worker **锁外** `juice_get_state`（禁止在 juice 回调或持 `mu_` 的 tick 里查 juice）。新 agent 已 CONNECTED/COMPLETED 再回锁 `set_connected`。stderr 立刻 `fflush`，避免 `kill -9` 吞日志。

`set_connected` 先处理 `ice_restarting`，再处理「中继升直连」，避免中继会话重启永远记不上。

### 2.2 客户端：`IOTC_Connect` 超时后 `stop()` 可能挂

超时只清 SID，不 `disconnect`，ICE agent 还在。`tick_ice` 曾在持锁时调 `juice_set_remote_gathering_done`，和 libjuice 线程形成 ABBA。

**修法**：超时锁外 `disconnect`；`stop()` 同时回收 `juice` 与 `juice_prev`。
`juice_set_remote_gathering_done` **仍在 tick 持锁调用**（锁外调用会与 juice 回调并发 `juice_*`，[3]/[5] 会出现单边 CONNECTED）。

### 2.3 服务端：管理统计口未鉴权

文档写 ADMIN_STATS 要 `AdminSecret`，代码是空负载谁都能问在线数。

**修法**：配了 `AdminSecret` 时要求 32 字节 `HMAC(secret, msg_id)`；未配置仍放行（本地/CI）。

### 2.4 中继：密钥写死、配额只增不减

`p2p-proxy-auth-2024` 写在客户端和 Proxy 两处。配额按 UID 累加，timer 不重置。

**修法**：`core/foundation/ProxyAuth.h`，`P2P_PROXY_AUTH_SECRET` 覆盖，默认值不变（测试不破）。配额每小时清一次。

### 2.5 构建：服务端误链 libjuice

NatServer / Proxy / Wake 从不调 `juice_*`，却链进约 325KB 静态库。

**修法**：`LDFLAGS_SSL` 给服务端；客户端/IOTC 仍链 juice。`clean` 补上 `server/wakeserver/bin`。

### 2.6 其它卫生

- `server/common/ProtoDef.h` 曾是 `PROTO_VER=0x01` 的死副本，已改成转发头。
- `AntiAbuse::flood_` 窗口过期后条目不删，`sweep` 时清空队列。

## 3. 明确不改

| 项 | 原因 |
|----|------|
| `force_relay` | [2]/[11]/[21] 依赖「硬关打洞」 |
| juice 回调里任何 `juice_*` | 与 `mu_` 死锁 |
| 持 `mu_` 的 tick 里查 juice | 同上 |
| RegistrySync 三条日志原文 | [6]/[8] grep |
| `p2p_node_region` 标签形状 | [12] |
| 把业务转发塞回 NatServer | 架构红线 |
| P9–P11 / TUN / mesh / `--p2p-only` | 产品不是 SD-WAN |

---

## 4. 架构债（分析，本轮只点到为止）

| 债 | 说明 | 要不要现在拆 |
|----|------|--------------|
| `P2PClient.cpp` 仍大 | 门面该大；状态机已按 tick_* 切 | 再拆收益低于 ICE/停机修复 |
| `NatServer.cpp` 仍含 JSON/metrics | 可再抽 `StatusSnapshot` | 非功能缺口 |
| Proxy TCP session `detach` | 进程退出不 join | 生产优雅停机再做 |
| WakeTrigger 无 HMAC | 协议要扩字段 | 需要兼容期，单独立项 |
| 手写 AES 仍在 | 隧道已有 AEAD；心跳 XOR 是兼容路径 | 不在本轮换算法 |

---

## 5. 不算本仓库「未完成」

| 项 | 原因 |
|----|------|
| 10 万心跳 / Relay 500Mbps | 压测机与现网容量 |
| 真 `tc netem` / docker+iptables NAT 矩阵 | 本环境无 iptables/`ip`，`unshare` 被拒 |
| Android / iOS / Windows SDK 包 | 打包与 CI，不是协议 |
| 弱网 1080p / 唤醒出图 <6s | 真机与码流 |
| SFU / 28181 / WHIP / MoQ | 旁路网关 |

## 6. 配置增量

| 键 | 作用 |
|----|------|
| `P2P_PROXY_AUTH_SECRET` | 覆盖中继注册 HMAC；空=演示默认（与历史测试兼容） |
| `AdminSecret` | 现在也管 `MSG_ADMIN_STATS_REQ`（有密钥才校验） |

覆盖顺序仍是：文件 < 已设置的 `P2P_*` < 命令行。
