> 适用项目：p2p_server_byding
> 服务器环境：Ubuntu（腾讯云 Lighthouse）
> 公网 IP：43.136.55.143

## 一、项目构建

### 1.1 依赖检查

```bash
# 确认 g++ 支持 C++17
g++ --version  # 需要 g++ 8.0+

# 确认 libjuice 静态库已编译
ls -la third_party/libjuice/build/libjuice.a
```

如果 `libjuice.a` 不存在，先编译 libjuice：

```bash
cd third_party/libjuice
mkdir -p build && cd build
cmake .. -DJUICE_STATIC=ON
make -j$(nproc)
cd ../../..
```

### 1.2 编译全部组件

```bash
cd /home/p2pserver/hu_p2p/p2p_server_byding
make -j$(nproc) all
```

构建产物：

| 二进制 | 路径 | 说明 |
|--------|------|------|
| `p2p_natserver` | `server/natserver/bin/p2p_natserver` | NAT 汇聚/打洞协调服务端 |
| `p2p_proxy` | `server/proxyserver/bin/p2p_proxy` | UDP 中继代理（TURN 兜底） |
| `peer` | `client/bin/peer` | 客户端 SDK 演示程序 |
| `crypto_test` | `tests/bin/crypto_test` | 加密模块单元测试 |

### 1.3 清理重建

```bash
make clean && make -j$(nproc) all
```

## 二、服务端启动

### 2.1 快速启动（本地测试）

使用项目自带脚本，默认绑定 `127.0.0.1`，适合本机测试：

```bash
cd /home/p2pserver/hu_p2p/p2p_server_byding
./start.sh
```

启动内容：
- NatServer：端口 `16001`（UDP）
- P2PProxy：端口 `16002`（UDP），最大中继 100 连接

停止服务：

```bash
./stop.sh
```

### 2.2 生产环境启动（公网访问）

> ⚠️ 生产环境需将绑定地址改为公网 IP `43.136.55.143`

```bash
cd /home/p2pserver/hu_p2p/p2p_server_byding

# 启动 NatServer（公网 IP + 端口 16001）
./server/natserver/bin/p2p_natserver 16001 16002 43.136.55.143 &

# 等待 NatServer 就绪
sleep 2

# 启动 P2PProxy（端口 16002，最大 100 中继）
./server/proxyserver/bin/p2p_proxy 16002 100 &
```

### 2.3 带鉴权启动

创建配置文件（如 `P2pServers.cfg`）：

```ini
# 基础配置
NatServer1=43.136.55.143
Proxy1_1=43.136.55.143

# 启用鉴权
EnableAuth=1
AuthSecret=s3cr3t

# 启用 UUID 白名单（可选）
# EnableLicense=1
# AllowedUuids=device001,device002

# 性能调优
ProcWorkers=4
RecvThreads=2

# 防滥用
FloodPktThreshold=200
BlacklistSeconds=60
```

NatServer 会自动读取同目录下的 `P2pServers.cfg`，也可通过命令行参数指定配置路径。

### 2.4 防火墙端口放行

> ⚠️ 腾讯云 Lighthouse 需在控制台防火墙规则中放行 UDP 端口

需要放行的端口：

| 端口 | 协议 | 用途 |
|------|------|------|
| 16001 | UDP | NatServer 信令/打洞协调 |
| 16002 | UDP | P2PProxy 中继转发 |
| 16003 | TCP | StatusServer 状态查询（可选） |

### 2.5 验证服务端启动

```bash
# 检查进程
ps aux | grep p2p_

# 检查端口监听
ss -ulnp | grep -E '16001|16002'

# 查看状态服务（如果启用了 StatusServer）
curl http://127.0.0.1:16003/stats 2>/dev/null || echo "StatusServer 未启用"
```

## 三、客户端测试

### 3.1 客户端命令行用法

```bash
./client/bin/peer <NatServerIP> <NatServerPort> <UUID> [对端UUID] [ProxyIP] [ProxyPort] [-s secret] [-relay]
```

参数说明：

| 参数 | 必填 | 说明 |
|------|------|------|
| `NatServerIP` | ✅ | NatServer 的 IP 地址 |
| `NatServerPort` | ✅ | NatServer 的 UDP 端口（如 16001） |
| `UUID` | ✅ | 本机节点 UUID（≤32 字符） |
| `对端UUID` | ❌ | 要连接的对端 UUID（不填则为等待方） |
| `ProxyIP` | ❌ | 中继代理 IP |
| `ProxyPort` | ❌ | 中继代理端口 |
| `-s secret` | ❌ | 鉴权密钥（服务端开启 EnableAuth 时必填） |
| `-relay` | ❌ | 强制走中继模式（跳过打洞） |

### 3.2 测试场景一：直连 P2P（无鉴权）

> 前提：服务端以无鉴权模式启动

**终端 A（等待方）：**

```bash
./client/bin/peer 43.136.55.143 16001 device001
```

预期输出：
```
[peer] started uuid=device001 local_port=xxxxx
[peer] ready pub=43.136.55.143:xxxxx nattype=full-cone
```

**终端 B（发起方）：**

```bash
./client/bin/peer 43.136.55.143 16001 device002 device001
```

预期输出：
```
[peer] started uuid=device002 local_port=xxxxx
[peer] ready pub=43.136.55.143:xxxxx nattype=full-cone
[peer] connecting to device001...
[peer] CONNECTED to device001 via direct
[peer] recv from device001 ch=1 [xxB]: hello from device001
```

### 3.3 测试场景二：中继模式（-relay）

**终端 A（等待方）：**

```bash
./client/bin/peer 43.136.55.143 16001 device001 43.136.55.143 16002 -relay
```

**终端 B（发起方）：**

```bash
./client/bin/peer 43.136.55.143 16001 device002 device001 43.136.55.143 16002 -relay
```

预期输出：
```
[peer] CONNECTED to device001 via relay
```

### 3.4 测试场景三：鉴权 + 加密

> 前提：服务端配置 `EnableAuth=1`、`AuthSecret=s3cr3t`

**终端 A（等待方）：**

```bash
./client/bin/peer 43.136.55.143 16001 device001 -s s3cr3t
```

**终端 B（发起方）：**

```bash
./client/bin/peer 43.136.55.143 16001 device002 device001 -s s3cr3t
```

预期输出：
```
[peer] ready pub=43.136.55.143:xxxxx nattype=full-cone
[peer] CONNECTED to device001 via direct
[peer] tunnel-enc tx=1 rx=1
```

> `tunnel-enc tx/rx` 表示隧道负载加密已启用

### 3.5 测试场景四：UUID 白名单

> 前提：服务端配置 `EnableLicense=1`、`AllowedUuids=device001,device002`

白名单内的 UUID 可以正常连接，白名单外的 UUID 会被拒绝：

```bash
# 白名单内 - 正常连接
./client/bin/peer 43.136.55.143 16001 device001 -s s3cr3t

# 白名单外 - 被拒绝
./client/bin/peer 43.136.55.143 16001 hacker001 -s s3cr3t
# 预期：连接失败或鉴权被拒
```

## 四、自动化测试

### 4.1 运行完整测试套件

项目内置 `test.sh`，覆盖直连/中继/鉴权/ICE/LAN/Token/调度等（见下表）：

```bash
cd /home/p2pserver/hu_p2p/p2p_server_byding
make -s all && bash test.sh
```

### 4.2 测试用例说明

| 序号 | 测试名称 | 验证内容 | 关键配置 |
|------|----------|----------|----------|
| 1 | 直连 P2P（无鉴权） | direct 连接 + NAT 类型检测 + 数据收发 | 无 |
| 2 | 中继兜底 | relay 连接 + proxy 注册 | `-relay` |
| 3 | 鉴权 + 加密心跳 | auth login + 加密心跳 + 多收包线程 | `EnableAuth=1`、`AuthSecret=s3cr3t`、`RecvThreads=3` |
| 4 | UUID 白名单 | 白名单内通过、白名单外拒绝 | `EnableLicense=1`、`AllowedUuids=WW,XX` |
| 5 | 打洞数据面加密 | tunnel-enc 加密帧收发 | `AuthSecret=s3cr3t` |
| 6 | 多 NatServer 同步 | 跨服 sync entry + ICE_SDP 转发 + cross-server 连接 | `SyncPeers=1`、`SyncAddrs=...` |
| 7 | 黑名单持久化 | admin 增删查 + 落盘恢复 | `BlacklistFile`、`AdminSecret=admsecret` |
| 8 | 跨服同步鉴权 | HMAC 签名同步/ICE_SDP + 伪造 MAC 拒绝 | `SyncAuthSecret=sharedsec` |
| 9–11 | UID / IOTC / 中继四通道 | 结构化 UID、AV/RDT/Tunnel、force_relay | `UidStrict=1`、`iotc_demo` |
| 12 | 区域调度 + STUN + metrics | GET_SERVER_LIST 就近、Binding、Prometheus | `Region` / `NatRegions` |
| 13 | wakeserver | KEEP / TRIGGER / POKE + NatServer 转发 | `WakeServer=` |
| 14 | 连线 Token | 缺/过期/错 src/重放拒绝，合法 Token 直连 | `EnableConnectToken=1` |
| 15 | LAN 组播发现 | `LAN found` + 仍走 P2P 直连 | `239.255.77.89:17890` |
| 16 | ICE restart | 换 ufrag 重建 agent，旧路径扛媒体 | `peer -restart` |
| 17 | TURN-over-443 | Proxy 兼听 alt 端口走中继 | `p2p_proxy … AltPort`、`ProxyAltPort` |
| 18 | DERP TCP/TLS 强制中继 | `-tcp -tls -relay` | `TcpPort` + 自签 TLS |
| 19 | DERP 先通再切 | `-tcp -tls` 并行 ICE | `via relay` → `via direct` |
| 20 | AltPort 兼听 TCP | 只配 AltPort | CONNECT 宣告 TCP、双栈 443 |

默认 `P2P_DISABLE_LAN=1`，仅 [15] 打开组播，避免用例互相串扰。
本机回环测试跳过 juice STUN（host 候选即可），公网部署仍指向 NatServer。
`test.sh` 用 `pkill -f` 清残留（本环境无 `killall`）；NatServer `SO_REUSEPORT`
若残留旧进程，UDP 会被分流，表现为随机鉴权失败或直连超时。

## 五、配置文件详解

### 5.1 完整配置项

```ini
# ===== 基础配置 =====
NatServer1=43.136.55.143          # NAT 汇聚服务端（可多台）
Proxy1_1=43.136.55.143            # 中继代理（可多个）

# ===== 鉴权配置 =====
EnableAuth=1                      # 启用强制鉴权
AuthSecret=s3cr3t                 # HMAC-SHA256 密钥

# ===== 白名单配置 =====
EnableLicense=1                   # 启用 UUID 白名单
AllowedUuids=device001,device002  # 白名单 UUID 列表

# ===== 性能调优 =====
ProcWorkers=4                     # 业务处理线程数
RecvThreads=2                     # UDP 收包线程数（SO_REUSEPORT）

# ===== 防滥用 =====
FloodPktThreshold=200             # 防洪水阈值（pps）
BlacklistSeconds=60               # IP 拉黑时长（秒）
BlacklistFile=/data/p2p_bl.bin    # 黑名单持久化文件
AdminSecret=admsecret             # 管理接口密钥

# ===== 多服同步 =====
SyncPeers=1                       # 启用注册表同步
SyncAddrs=10.0.1.2:16001          # 同步对端地址
SyncAuthSecret=sharedsec          # 同步消息 HMAC 密钥
```

### 5.2 配置热加载

NatServer 运行时检测配置文件修改时间（`cfg_mtime_`），自动热加载新配置，无需重启服务。

## 六、管理接口

### 6.1 黑名单管理

通过 UDP 发送管理报文（magic=0x584E, msg_id=0x1D）进行黑名单管理：

| 操作码 | 功能 | 说明 |
|--------|------|------|
| 1 | 加 IP | 将指定 IP 加入黑名单 |
| 2 | 删 IP | 将指定 IP 移出黑名单 |
| 3 | 加 UUID | 将指定 UUID 加入黑名单 |
| 4 | 删 UUID | 将指定 UUID 移出黑名单 |
| 5 | 查询 | 查询当前黑名单列表 |

管理报文需携带 `AdminSecret` 的 HMAC-SHA256 签名，否则被拒绝。

### 6.2 状态查询

如果启用了 StatusServer（TCP 端口），可通过 HTTP 请求查询状态：

```bash
curl http://127.0.0.1:16003/stats
```

返回 JSON 格式的统计信息：在线节点数、设备数、客户端数、黑名单数、代理可用数、连接成功/失败计数。

## 七、常见问题排查

### 7.1 客户端无法连接

```bash
# 1. 检查服务端是否运行
ps aux | grep p2p_natserver

# 2. 检查端口是否监听
ss -ulnp | grep 16001

# 3. 检查防火墙是否放行 UDP
# 腾讯云控制台 -> 防火墙规则 -> 添加 UDP 16001/16002

# 4. 检查鉴权密钥是否匹配
# 服务端 AuthSecret 和客户端 -s 参数必须一致
```

### 7.2 打洞失败降级中继

```bash
# 查看客户端日志是否显示 relay
[peer] CONNECTED to device001 via relay

# 检查 P2PProxy 是否运行
ps aux | grep p2p_proxy

# 如果需要强制中继测试
./client/bin/peer 43.136.55.143 16001 device002 device001 43.136.55.143 16002 -relay
```

### 7.3 鉴权失败

```bash
# 检查服务端日志
tail -f /tmp/nat.log

# 常见错误：
# - AUTH_BAD_MAC: 密钥不匹配
# - AUTH_BLACKLIST: IP/UUID 被拉黑
# - AUTH_WHITELIST_REJ: UUID 不在白名单
```
